# Цель

Перенести клиентский PrimeTime в независимый публичный GitHub Pages `primetime-booking/primetime-booking.github.io`, не затрагивая PrimeTime Pro и «Анатомию массажиста».

# Сделано

- Создан отдельный публичный репозиторий организации.
- Перенесены клиентские страницы и необходимые общие зависимости из `minuta-online-booking/`.
- Добавлены отдельные manifest, service worker/cache и Pages workflow.
- Добавлены независимые браузерные проверки источников привлечения и восстановления групповой записи.

# Проверено

- Статические проверки клиентского состава, JavaScript и основного booking-flow проходят.
- Локальный сайт загрузил реальные услуги и свободное время; путь «услуга → время → контакты» пройден без создания записи.
- Интерфейс проверен на 390, 760 и 1440 px без горизонтального переполнения.
- Service worker зарегистрирован и загрузил собственный клиентский набор PWA-ресурсов.
- GitHub Actions verify/deploy прошёл для `2a2047a9a543c1b39ae6797a45ba7263aefe5397`.
- Live `https://primetime-booking.github.io/` и `/#/home` отдают клиентский PrimeTime; на 390, 760 и 1440 px нет горизонтального переполнения.
- На live пройден путь «услуга → ближайшее время → контакты» без отправки формы; ошибок браузера не обнаружено.
- Добавлены ограничение ожидания доступности, безопасный повтор запроса и защита от устаревшего ответа; проверено отсутствие бесконечного индикатора загрузки.
- Клиент сначала запрашивает компактный RPC v165 и при его отсутствии автоматически возвращается к прежнему RPC v101.
- SQL v165 проверен в PGlite: 1680 слотов собраны в 14 строк без изменения результата; повторное применение и откат проходят.
- GitHub Actions verify/deploy прошёл для `ed453efe6f59ee87e2bf640946a76a001a23ea4a`.
- Старый клиентский URL перенаправляет на новый адрес с сохранением query/hash; «Анатомия массажиста» и PrimeTime Pro не перенаправляются.
- Отдельные клиентские проверки привлечения и восстановления записи, а также Pages-публикация успешно прошли для `fddc66cbb5f108c3079d0b2c5de275971d3802d9`.

# Зафиксированные решения

- Старый адрес тренажёра `anatomy-trainer/#/home` не изменяется.
- Кабинет исполнителя остаётся в исходном репозитории; клиентские ссылки на него ведут на прежний адрес.
- Используется существующий публичный Supabase backend без service-role ключей и изменений данных.
- Перенаправление включено только на production-хосте старого Pages и сохраняет параметры URL и hash-маршрут.

# Ограничения и блокеры

- Компактные RPC v165 ещё отсутствуют в production-БД; опубликованный клиент корректно использует fallback v101.
- Production-миграция не применялась: в текущей задаче не было разрешения и подтверждённого доступа для изменения базы.
