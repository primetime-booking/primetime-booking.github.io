# Цель

Перенести клиентский PrimeTime в независимый публичный GitHub Pages `primetime-booking/primetime-booking.github.io`, не затрагивая PrimeTime Pro и «Анатомию массажиста».

# Сделано

- Создан отдельный публичный репозиторий организации.
- Перенесены клиентские страницы и необходимые общие зависимости из `minuta-online-booking/`.
- Добавлены отдельные manifest, service worker/cache и Pages workflow.
- Добавлены независимые браузерные проверки источников привлечения и восстановления групповой записи.
- В «Моих записях» явно показано восстановление на другом устройстве по номеру телефона и личному коду из сохранённого после записи файла.
- Если вход по SMS недоступен, форма восстановления раскрывается автоматически; SMS и другие внешние уведомления не отправляются.

# Следующие шаги

1. Реализовать голосовой запрос с явным подтверждением перед записью, не выполняя бронирование автоматически.
2. После отдельного разрешения на production-БД применить миграцию v165 по проектному регламенту: свежий бекап, тестовая миграция и проверка отката.
3. После применения проверить отсутствие fallback и фактическое уменьшение payload на production.

# Зафиксированные решения

- Старый адрес тренажёра `anatomy-trainer/#/home` не изменяется.
- Кабинет исполнителя остаётся в исходном репозитории; клиентские ссылки на него ведут на прежний адрес.
- Используется существующий публичный Supabase backend без service-role ключей и изменений данных.
- Перенаправление включено только на production-хосте старого Pages и сохраняет параметры URL и hash-маршрут.

# Ограничения и блокеры

- Компактные RPC v165 ещё отсутствуют в production-БД; опубликованный клиент корректно использует fallback v101.
- Production-миграция не применялась: в текущей задаче не было разрешения и подтверждённого доступа для изменения базы.
