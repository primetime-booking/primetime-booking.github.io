# Убрать старый самостоятельный экран записи

Этот кандидат зависит от сначала опубликованного canonical `/legacy-booking` в современном Eldion. Пользователь разрешил внедрение двух пунктов: переход вместо старой страницы и полезные FAQ в Eldion. Пока рабочая приёмка 0/2.

В `catalog-router.js` причиной дубля был ранний return для org/service/provider/location/group. Теперь прямые ссылки корня уходят в same-origin Eldion bridge с сохранением контекста и attribution; повторные/невалидные значения сохраняются для отказа на стороне bridge. Неизвестный fragment и embedded/group контекст не выдаются за обычную запись. Обычный корневой вход и канонические `/r/`, `/master/` и каталог сохраняют прежний контракт.

Исторические `/booking.html`, `/my-bookings.html`, `/messages.html`, политика и существующие данные не удалены и не перенаправляются этим изменением. Шаблон/скрипты прежнего booking-flow сохранены для этих сценариев и регрессии; опубликованный корневой direct-link больше не выбирает его.

Версии согласованы: router 8, service worker/cache-ready/site-update 9 и соответствующие HTML. Изолированный PWA тест для старых v7 и v8 доказывает загрузку нового router 8, переход вместо старой формы, сохранность чужого кеша и отсутствие принудительного ухода со страницы управления исторической записью. При неудачном precache сохраняется прежний полный offline cache, как раньше.

Локально PASS: syntax JS, client-pages-static, router, PWA upgrade, SW cache failure, availability loading/compact, public booking-flow, обязательная неизменённая v165 migration/rollback в PGlite. В браузере исходный реальный экран зафиксирован; тот же HTML и router в изолированном harness прошли переход в synthetic GET bridge, где старые hero/form отсутствуют. FAQ проверен на 390/760/1440 в современном отдельном кандидате. Это не live доказательство нового bridge.

ROOT — единственный издатель этого Pages-пакета. Перед merge: актуальный remote main, SHA/CI, опубликованный bridge и read-only проверка actual org/service/performer/location. После выпуска: фактические router/SW версии, старая реальная ссылка, отсутствие прежней формы и сохранность исторических путей. Pro redirect/common resources этот кандидат не меняет.
